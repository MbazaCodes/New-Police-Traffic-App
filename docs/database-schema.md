# Database Schema

This document describes the PostgreSQL schema for the Tanzania Police
Digital Platform. The canonical source is `packages/database/src/schema.sql`
— this doc is a human-readable summary. Run `npm run db:migrate` to apply
the schema to a fresh database.

## 1. Extensions

```sql
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "pgcrypto";
```

All primary keys are UUIDs generated by `uuid_generate_v4()`. The
`pgcrypto` extension is used for hashing OTP codes and audit-log digests.

## 2. Core tables (14 tables)

### users

The central identity table. Every human who logs in (officer, clerk,
admin, citizen) has a row here.

| Column           | Type         | Notes                                      |
|------------------|--------------|--------------------------------------------|
| id               | UUID PK      | `uuid_generate_v4()`                       |
| name             | VARCHAR(255) | Full name                                  |
| short_name       | VARCHAR(100) | Display name (optional)                    |
| rank             | VARCHAR(100) | Police rank (e.g. `Inspector`)             |
| role             | VARCHAR(50)  | RBAC role — see `src/lib/rbac.ts`          |
| id_number        | VARCHAR(50)  | National ID, unique                        |
| station_id       | UUID FK      | → `stations(id)`                           |
| phone            | VARCHAR(20)  | Unique, used for OTP login                 |
| email            | VARCHAR(255) | Unique, optional                           |
| password_hash    | VARCHAR(255) | bcrypt hash                                |
| status           | VARCHAR(20)  | `active` / `off-duty` / `on-leave` / `suspended` |
| last_login       | TIMESTAMPTZ  | Updated on each login                      |
| created_at       | TIMESTAMPTZ  | Default `NOW()`                            |
| updated_at       | TIMESTAMPTZ  | Default `NOW()`, updated by trigger        |

### stations

Police stations. Each station belongs to a region and district.

| Column      | Type         | Notes                                  |
|-------------|--------------|----------------------------------------|
| id          | UUID PK      |                                        |
| name        | VARCHAR(255) |                                        |
| region      | VARCHAR(100) | Used for regional scoping              |
| district    | VARCHAR(100) |                                        |
| phone       | VARCHAR(20)  |                                        |
| status      | VARCHAR(20)  | `active` / `maintenance` / `inactive`  |

### posts

Sub-stations or patrol posts under a station.

| Column      | Type         | Notes                                  |
|-------------|--------------|----------------------------------------|
| id          | UUID PK      |                                        |
| name        | VARCHAR(255) |                                        |
| station_id  | UUID FK      | → `stations(id)` ON DELETE CASCADE     |
| type        | VARCHAR(20)  | `Traffic` / `Patrol`                   |
| shift       | VARCHAR(100) | e.g. `Day`, `Night`                    |

### officers

Officer profile (1:1 with `users` for officer roles). Denormalized
counters for fast dashboard rendering.

| Column           | Type         | Notes                                  |
|------------------|--------------|----------------------------------------|
| id               | UUID PK      |                                        |
| user_id          | UUID FK      | → `users(id)` ON DELETE CASCADE        |
| officer_number   | VARCHAR(50)  | Unique badge number                    |
| station_id       | UUID FK      | → `stations(id)`                       |
| post_id          | UUID FK      | → `posts(id)`                          |
| status           | VARCHAR(20)  | `active` / `break` / `off-duty`        |
| patrols_count    | INT          | Denormalized counter                   |
| citations_count  | INT          | Denormalized counter                   |
| incidents_count  | INT          | Denormalized counter                   |
| hours_today      | DECIMAL(4,1) | Patrol hours today                     |

### assignments

Maps officers to stations/posts over time. Historical record — even after
an officer transfers, their old assignments remain for audit.

### vehicles

Registered vehicles. `plate` is the primary lookup key.

### drivers

Licensed drivers. Linked to `users` if the driver is also a platform user
(citizen), otherwise standalone.

### citizens

Citizen profiles for the citizen portal. Separated from `users` because
not all citizens have platform accounts (some are referenced in
citations/incidents without ever logging in).

### citations

Traffic citations issued by officers. Linked to `officers`, `vehicles`,
and `drivers`.

### incidents

Traffic incidents (accidents, reports). Linked to `officers` and
optionally to `vehicles`/`drivers`.

### patrols

Patrol logs. Each patrol has a start/end time, route, and assigned
officers.

### alerts

System alerts (e.g. stolen vehicle, wanted person). Broadcast to all
officers in the relevant region.

### pf3_forms

PF3 accident report forms — the official Tanzanian police accident
report document. Stored as structured JSON plus a generated PDF blob.

### vehicle_inspections

Vehicle inspection records. Each inspection has a checklist of pass/fail
items and an overall result.

## 3. Audit & log tables (separate schema)

The following tables live in the same database but are owned by the
audit subsystem:

- `audit_logs` — every mutating action, append-only
- `activity_logs` — user activity feed (login, page views, etc.)
- `otp_codes` — hashed OTP codes with expiry

See `packages/database/src/schema.sql` for the full DDL.

## 4. Indexes

All foreign keys have indexes. Additionally:

- `users.phone`, `users.email`, `users.id_number` — unique indexes
- `vehicles.plate` — unique index
- `citations.officer_id`, `citations.created_at` — composite index for
  the officer dashboard's "recent citations" query
- `audit_logs.user_id`, `audit_logs.created_at` — composite index for
  the admin audit-log viewer

## 5. Row Level Security (RLS)

RLS is currently NOT enabled. The application enforces data scoping in
the route handlers via `applyScopeToQuery`. A future migration will
enable RLS as defense-in-depth — see `docs/rls.md` (planned).

## 6. Migrations

Migrations live in `packages/database/migrations/`. Each migration is a
numbered SQL file (e.g. `001_initial.sql`, `002_add_citizen_points.sql`).
Apply them in order with:

```bash
npm run db:migrate
```

The migrate script tracks applied migrations in a `_migrations` table.
Never edit an applied migration — create a new one instead.
